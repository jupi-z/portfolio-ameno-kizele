# Contact delivery

The form requires a name, valid email, international phone number, subject and message of at least 30 characters. These rules are checked in the browser and repeated by the API. When SMTP is configured, requests are sent as a styled HTML and plain-text email to the business inbox with the two owner addresses in CC. The visitor's address is used only as `Reply-To`; no automatic acknowledgement is sent.

Configure the deployment environment with Hostinger's authenticated SMTP settings: `SMTP_HOST=smtp.hostinger.com`, port `465` with `SMTP_SECURE=true` (or the provider-approved TLS submission port `587` with `SMTP_SECURE=false`), and the full mailbox address as `SMTP_USER`. `CONTACT_FROM` must be the authenticated mailbox, `CONTACT_TO` the business inbox, and `CONTACT_CC` a comma-separated list of copy recipients. Keep the rotated mailbox password in a root-owned secret file or the VPS secret manager only; never commit it, paste it into code, or use a `NEXT_PUBLIC_` variable. If settings are absent, the API returns `503 transport_not_configured` and offers an honest prepared-email fallback; it does not claim the message was sent.

The handler limits the request size and field lengths, rejects header newlines, validates the email, uses a hidden honeypot and a per-process rate limiter (five requests per 15 minutes). Behind the included Nginx proxy it uses the rightmost `X-Forwarded-For` address, which Nginx appends from its observed peer address. The limiter is intentionally not described as distributed: it resets on process restart and is not shared between workers. Add an approved shared limiter before deploying to a multi-instance environment if this level is insufficient. Message contents are not logged or persisted by this application. SMTP success does not guarantee inbox placement; configure SPF, DKIM and DMARC with the domain owner and verify delivery in the provider's approved test environment before production use.

Automated tests use synthetic input and an injected mock transport only. No real email is sent by the repository's tests. After setting a rotated credential, verify receipt to the inbox and both copies before enabling the form in production.
